# SCL Institute Development Workflow - MANDATORY

## Critical Workflow Rule - DO NOT BYPASS

**ALL code changes MUST follow this exact workflow:**

### ✅ CORRECT WORKFLOW
1. **Always work on `develop` branch** - never commit directly to production
2. **Make all changes locally** - test thoroughly before pushing
3. **Commit to develop** - push changes to develop branch
4. **Deploy to production ONLY when explicitly requested** - merge develop → production → deploy

### ❌ NEVER DO THIS
- ❌ Commit directly to `production` branch (unless reverting a broken deployment)
- ❌ Deploy to production server without testing on develop first
- ❌ Skip the develop → production → remote server workflow
- ❌ Use production branch for development work

## Git Workflow (STRICT)

```
1. git checkout develop
2. Make code changes locally
3. Test thoroughly on localhost (port 3000)
4. git add . && git commit -m "message"
5. git push origin develop
6. [WAIT FOR APPROVAL] - Only proceed with merge if asked
7. git checkout production && git merge develop
8. git push origin production
9. Deploy to 185.211.6.60 via SSH
```
